# 游戏架构演进计划

> 从当前五子棋单文件架构 → 面向 40+ 模块的企业级架构
> 分步迁移，每阶段可独立交付，不阻塞开发

---

## 阶段零：地基（1-2 天）

**目标**：搭好基础设施，不改任何游戏功能

```
assets/Script/
├── frameworks/
│   └── ServiceRegistry.ts      ← 新文件
├── services/                    ← 从 manager/ 搬过来
│   ├── AudioService.ts
│   ├── StorageService.ts
│   ├── TimeService.ts
│   └── EventBus.ts
└── base/
    └── BaseUI.ts               ← 重构，用 ServiceRegistry 替代硬 import
```

### 具体步骤

| # | 操作 | 结果 |
|---|------|------|
| 0.1 | 新建 `frameworks/ServiceRegistry.ts` | 注册表 + Proxy 生成 |
| 0.2 | 建 `services/`，把 `AudioManager` `TimeManager` `EventEmitter` 搬过来改名 | 服务层形成 |
| 0.3 | 建 `AppServices.ts`，所有服务一次性注册 | 唯一 import 集中的地方 |
| 0.4 | 重构 `BaseUI`，用 getter 映射替代 9 行硬 import | 子类调用方式不变 |
| 0.5 | 验证所有现有界面能正常运行 | |

**风险**：无（纯新增 + 搬运，不改已有逻辑）

---

## 阶段一：核心框架（2-3 天）

**目标**：UIManager 拆分、模块管理器雏形、全局配置规整

```
assets/Script/frameworks/
├── ServiceRegistry.ts       ← 已有
├── ModuleManager.ts         ← 新文件（模块注册/生命周期）
├── UIManager.ts             ← 重构（拆出路由）
├── PopupManager.ts          ← 保持不动
└── ResourceManager.ts       ← 新文件（资源按模块加载释放）
```

### 具体步骤

| # | 操作 | 结果 |
|---|------|------|
| 1.1 | UIManager 拆分：路由配置加载抽到 `RouteConfig.ts`，预制体缓存抽到 `PrefabCache.ts` | UIManager 只负责栈管理 |
| 1.2 | 页面栈加 `MAX_DEPTH` 和防重复 | 防止栈无限增长 |
| 1.3 | 新建 `ModuleManager.ts`（模块注册、onLoad/onUnload 生命周期） | 模块化的入口 |
| 1.4 | 新建 `ResourceManager.ts`（按 `ModuleResources/xxx/` 路径加载/释放） | 资源隔离 |
| 1.5 | `EventBus` 与 `SettingManager` 解耦（事件通知代替直接调 AudioManager） | 消除循环依赖 |

**风险**：中。UIManager 拆分可能影响已有页面显示流程，需要回归测试。

## 阶段二：网络层接入（2-3 天）

**目标**：网络层独立，和后端约定协议结构

```
assets/Script/network/
├── NetworkService.ts           ← 新文件
├── connection/
│   ├── WebSocketConnector.ts   ← 新文件
│   ├── HeartBeatManager.ts     ← 新文件
│   └── ReconnectManager.ts     ← 新文件
├── protocol/
│   ├── msg_id.ts               ← 新文件（和后端商定后填充）
│   └── types/                  ← 新文件
├── handlers/
│   └── MessageDispatcher.ts    ← 新文件
└── codec/
    └── JsonCodec.ts            ← 新文件（初始用 JSON，可替换 Protobuf）
```

### 具体步骤

| # | 操作 | 结果 |
|---|------|------|
| 2.1 | 搭建 `network/` 目录和 `NetworkService` 统一接口 | 模块调用 `this.svc.Network.send()` |
| 2.2 | 实现 WebSocket 连接、心跳、断线重连 | 底层通信就绪 |
| 2.3 | 实现 `MessageDispatcher`（msg_id → handler） | 消息分发 |
| 2.4 | 和后端商定 `msg_id.ts` + 数据结构，填入 `protocol/` | 协议定义完成 |
| 2.5 | 注册 `NetworkService` 到 `ServiceRegistry` | 模块可直接调用 |

**风险**：低。网络层是增量新增，不修改现有游戏逻辑。

## 阶段三：模块化迁移（持续）

**目标**：把现有功能逐步拆成模块

```
assets/Script/modules/
├── login/                  ← 从 LoginLayer.ts 拆出
├── battle/                 ← 从 BattleLayer + Chess + AI 拆出
│   ├── BattleModule.ts
│   ├── ui/
│   │   ├── BattleMain.ts
│   │   └── GameInfoUI.ts
│   ├── ai/
│   │   └── AIController.ts
│   ├── handlers/
│   │   └── BattleHandlers.ts
│   └── config/
├── setting/                ← 从 SettingLayer 拆出
├── replay/                 ← 从 ReplayUI + ReplayManager 拆出
└── ...
```

### 迁移规则

- **每次拆一个**模块，拆完验证，再拆下一个
- 模块边界清晰：一个模块的代码**只在自己目录**里改，不动别人的文件
- 模块间通信：只走 `EventBus` 或 `NetworkService`，不 import 对方的类

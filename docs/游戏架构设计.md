# 游戏架构设计

> 五子棋练手 → 面向 40+ 模块、多人协作的企业级游戏架构

---

## 核心设计原则

### 1. 零 import 调用

模块内部调用服务时，不需要写任何 import 语句。

```typescript
// 模块里这样写，不 import 任何服务
this.svc.Network.send('msg_login', data);
this.svc.Audio.play('shoot');
this.svc.UI.show('shop_panel');
```

**实现方式**：ServiceRegistry + Proxy + BaseUI getter 映射。所有服务在项目入口处一次性注册，通过 `ServiceRegistry.createProxy()` 生成代理对象，模块通过继承 BaseUI 自动获得所有服务的访问能力。

**动机**：40+ 模块数百个文件，如果每个文件都写 import 会大量重复。集中注册、调用方零 import。

### 2. 代码与资源分离

```
assets/Script/          → 纯代码
assets/resources/       → 纯资源（预制体、纹理、配置表、音频）
```

同一模块的代码在 Script 中按模块分目录，资源在 resources 中按模块分目录，两者通过**模块 ID** 关联，不混放。

### 3. 模块自治

每个模块是一个独立的目录，包含：
- `ModuleName.ts` — 模块入口（生命周期）
- `ui/` — 本模块的界面逻辑
- `handlers/` — 本模块的网络消息处理
- `ai/` — 本模块的 AI 逻辑（如果需要）
- `config/` — 本模块的配置

**模块间不直接 import 对方的类**。通信方式：
- **模块 → 服务器**：通过 `NetworkService`
- **模块 ↔ 模块**：通过 `EventBus`

### 4. 纯联机，网络层是一等公民

网络层独立为顶层目录，不是 services 的附属。模块直接依赖 NetworkService，不经过 EventBus 绕路，调用链路最短。

## 核心机制

### ServiceRegistry + Proxy

```
【集中注册】
AppInit.ts 中一次性注册所有服务：
    registry
        .register('Audio', AudioService)
        .register('Network', NetworkService)
        .register('UI', UIManager)
        ...

【零 import 调用】
BaseUI 通过 getter 提供映射：
    get AudioManager() { return this.svc.Audio; }
    get Network() { return this.svc.Network; }

子类直接：
    this.AudioManager.play('shoot');
    this.Network.send('msg_login', data);

加新服务只需在 AppInit.ts 加一行 .register()，BaseUI 加一行 getter。
```

### 模块生命周期

```typescript
interface IGameModule {
    moduleId: string;
    dependencies: string[];
    onLoad(services: ServiceProxy): void;   // 模块加载（注册网络消息、初始化数据）
    onUnload(): void;                       // 模块卸载（释放资源、取消监听）
    onEnter(data?: any): void;              // 进入模块（显示界面）
    onLeave(): void;                        // 离开模块（隐藏界面）
}
```

### 网络消息流

```
模块调用 NetworkService.send(msg_id, data)
    → codec 编码
    → WebSocket 发送到服务器

服务器回包
    → WebSocket 接收
    → codec 解码
    → MessageDispatcher 根据 msg_id 分发给对应模块的 handler
```

协议格式（JSON / Protobuf）通过 `codec/` 层隔离，模块代码不感知。

### 资源按模块加载释放

```
ModuleManager 控制：
    进入模块 → ResourceManager.load('ModuleResources/lobby/')
    离开模块 → ResourceManager.release('ModuleResources/lobby/')
```

## 架构决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 服务调用方式 | ServiceRegistry + Proxy | 模块侧零 import，集中管理依赖 |
| 模块间通信 | EventBus | 不直接 import 对方模块，解耦 |
| 模块→服务器通信 | 直接依赖 NetworkService | 纯联机游戏，不绕 EventBus 增加链路 |
| 协议格式 | codec 层隔离 | 模块不感知协议，可后期从 JSON 切 Protobuf |
| 模块目录 | Script/ 下 modules/ | Cocos 2.4.3 只认 assets/Script/ 下代码 |
| 资源目录 | resources/ModuleResources/ | 运行时 `loadResDir` 按模块加载/释放 |
| 文档对象模式（基类） | 保留 BaseUI 继承 + getter 映射 | 子类调用最简洁，适合游戏场景 |
